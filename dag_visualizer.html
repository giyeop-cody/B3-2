📌 Kahn's Algorithm 위상 정렬 대화형 시뮬레이터

부모 커밋의 진입 차수(Indegree)가 0이 될 때 큐에 넣어 정렬함으로써, 부모 커밋이 자식 커밋보다 항상 먼저 출력되도록 만듭니다.

진행 단계: 0 / 4

현재 진입 차수 (Indegree Table)

c1: 0 | c2: 1 | c3: 1 | c4: 2

대기 큐 (Queue)

[ c1 ]

정렬 출력 결과 (Topological Output Log)

대기 중... '다음 단계' 버튼을 누르세요.
💡 초기 상태: 루트 커밋인 c1은 자식 관점에서 진입 차수(Indegree, 나를 가리키는 부모의 수)가 0이므로 대기 큐에 가장 먼저 들어갑니다.

📌 자료구조 비교: 왜 Git은 DAG를 선택했는가?

1. 선형 리스트 (Linear List)

(c1) ──► (c2) ──► (c3)

❌ 한계: 줄기가 1개뿐이므로 여러 개발자가 동시 작업하는 '브랜치 분기'를 만들 수 없습니다.

2. 트리 (Tree)

(c1) ──► (c2), (c3) 분기

❌ 한계: 자식이 갈라질 수는 있지만, 2개 이상의 부모를 가지는 '머지 커밋(Merge Commit)'을 생성할 수 없습니다.

3. DAG (Directed Acyclic Graph) ★

분기 및 머지(다중 부모) 완벽 지원

✅ 선택 이유: 브랜치 분기 및 머지 노드를 유연하게 표현하면서도, 순환(Cycle)이 없어 시간의 인과성을 완전 보장합니다.

⚠️ 만약 사이클(Cycle)이 생긴다면?
미래 커밋이 과거 커밋의 부모가 되는 '시간 여행 역설'이 발생합니다. 그 결과 모든 노드의 진입 차수가 1 이상이 되어 Kahn's Algorithm에서 큐에 들어갈 노드가 소멸하므로 위상 정렬이 불가능해집니다.

📌 PATH 명령을 위한 무방향 BFS 최단 경로 시각화

Git의 원본 포인터는 자식 $\rightarrow$ 부모 단방향입니다. 서로 다른 브랜치(c2: feature와 c3: main) 간 이동을 위해서 간선을 무방향(Undirected)으로 재정의한 후 BFS 레벨 탐색을 수행합니다.

탐색 경로 결과

Path: c2 -> c1 -> c3 (간선 거리: 2)

📌 역색인 (Inverted Index) O(1) 탐색 원리

🐢 선형 순회 (Linear Scan) - O(N × L)

Commit 1: "Initial commit" (검색 중...)
Commit 2: "Add payment feature" (검색 중...)
...
Commit 100000: "Add login" (발견!)
➡️ 10만 번 독해 후 탐색 완료 (매우 느림)

⚡ 역색인 해시맵 (Inverted Index) - O(1)

dict["initial"] ──► { c1 }
dict["login"] ──► { c2, c5 } ★ 즉시 반환!
dict["payment"] ──► { c3 }
➡️ 0.0001초 만에 해시 버킷 버퍼 조회 완료
