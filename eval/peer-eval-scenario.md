# B3-2 동료평가 시나리오

## 1. 학습
- 정렬 알고리즘 (버블, 퀵, 머지)
- 이진 탐색
- 파일 시스템 감지 (mtime, hash)

## 2. 고찰
- "sorted()가 어떤 알고리즘을 쓰는지" — Timsort
- "정렬이 왜 필요한지" — 이진 탐색의 전제

## 3. 시도
- mini-git: init, add, commit, diff, log, checkout
- 정렬 직접 구현 (버블 + 머지)

## 4. 수정
- mtime만으로 불충분 → hash 추가 (내용 기반)

## 5. 선택과 선정
- 버블 vs 퀵: 퀵 (빠름 but 복잡) → 구현 난이도 고려
- mtime vs hash: hash (내용 기반, 더 정확)

## 6. 트러블슈팅
- 정렬 안 됨 → 비교 함수 오류 수정
- 변경 감지 누락 → hash로 내용 비교 추가
