# 📦 Model 패키지 기술 문서 (`mini_git/model/`)

## 1. 개요 및 역할
`model` 패키지는 Mini Git 시스템의 **데이터 계층(Data Layer)**을 담당합니다. Git 그래프의 최소 단위 노드인 커밋 데이터를 표현하는 불변 객체 모델을 관리합니다.

---

## 2. 모듈 구성 및 코드 구조
* **`commit.py` (`CommitNode`)**: 단일 커밋의 메타데이터를 저장하는 불변 클래스.

---

## 3. 핵심 자료구조 및 설계 특성

### 1) `CommitNode` 클래스 필드
* `hash`: 세션 내 유일한 6자리 16진수 커밋 식별자 (`str`).
* `message`: 커밋 메시지 (`str`).
* `author`: 작성자 이름 (`str`).
* `timestamp`: 커밋 생성 시각 (`datetime.datetime`).
* `parents`: 부모 커밋 해시 리스트 (`list[str]`). 일반 커밋은 1개, 머지 커밋은 2개, 루트 커밋은 0개.
* `branch`: 커밋이 작성된 브랜치 이름 (`str`).

### 2) 객체 불변성 및 방어적 복사 (Defensive Copy)
```python
self.parents = list(parents)  # 방어적 복사
```
외부에서 전달받은 `parents` 리스트를 그대로 참조하지 않고 `list(parents)`로 새로 복사하여 할당함으로써, 외부 코드의 우발적 변경으로부터 커밋 그래프 노드의 데이터 정합성을 보장합니다.

---

## 4. 알고리즘 및 트레이드오프 분석
* **사용된 자료구조**: 불변 데이터 구조체 (`CommitNode`).
* **선정 이유**: 커밋 이력은 생성된 후 수정되지 않아야 하는 Git의 불변성 원칙(Immutability)을 반영하기 위함.
* **장단점**:
  * *장점*: 데이터 오염 차단, `__str__()` 유틸리티를 통한 명확한 포맷팅 출력.
  * *단점*: 커밋 객체 다수 생성 시 약간의 메모리 오버헤드.
* **판단 근거**: 커밋 이력 데이터 정합성과 방어적 복사를 통한 부작용 차단이 우선됨.
